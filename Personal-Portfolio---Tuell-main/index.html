VPN-Enabled Home Network Deployment

About This Project

This project involved implementing a Virtual Private Network, or VPN, directly on a home router rather than on individual devices, such as a phone or a laptop. Doing this allowes every device connected onto a Wi-Fi network, which includes devices that don't normally support VPN software, to be automatically protected.

Technical Details

  • Router Port Configuration: Replaced stock OS with a Linux-based alternative to support VPN protocols.
  • Router Custom Firmware: Mapped UDP/TCP ports to ensure the encrypted tunnel bypasses the local firewall.
  • Kill Switch: IP Table rules that drop all packets if the VPN interface goes down.

Challenges & Solutions

The first problem that I came across during this process was during the installation of the custom firmware. I tried to use a incompatible file version, which caused the router to brick. I had to preform a Trivial File Transfer Protocol, or TFTP recovery. It involved settinga static IP on a computer, connecting it via Ethernet, and pushing the factory frmware back onto the router. Another problem I experienced was due to the fact that my internet connection was a modem/router combination. When I connected my VPN-enabled router to the modem, it caused router port configuration problems. In order to fix it, I had to configure the ISP's modem to Bridge Mode, disabling the ISP's routing and firewall features. Finally, I was facing issues with the actual hardware with the router aswell, as my router's CPU was maxed out, causing high latency and low speeds. I found out this was caused by using OpenVPN, so I switched to WireGuard. I also enabled AES-NI, and overclocked the router.

SteamOS Modded Minecraft Server

About This Project

This project involved the Linux systems administration and game server virtuatlization to turn a SteamDeck console into a host for a modded Minecraft environment. This messed with java runtime scripts and environments, the linux file system, and the configuration of network ports to allow people from anywhere to join the server.

Technical Details

  • Java Runtime Environment: Installed and configured Java 21, involving the management of environmental variables.
  • Permissions & EULA: Utilized commands chmod, chown, nano, to manage file permissions and edit the eula.txt file.
  • Static IP Assignment: Ensured the SteamDeck has a consistent internal IP address within the local network.
  • Port Mapping: Configured the home router to foward TCP/UDP Port 25565 to the SteamDeck to bypass the firewall.

Challenges & Solutions

One of the first issues I ran into were system read-only errors, which was caused by SteamOS Immutability. My solution was to use the command steam-os-readonly disable, and to use flatpal-based JRE installations to bypass root restrictions. Another issue I had was with high latency caused by resource contention. My fix was tweaking with the JVM arguments to prioritize CPU threads for the server process over background Steam services. Lastly, when hosting the server, other people would have connectivity issues, which were caused by CGNAT and firewall blocks. I had to verify port 25565 was open using an external port checker, and I had to confirm the router's NAT settings.

Kubuntu, Kali, & Mint

About This Project

This project involved quad-booting Windows, Kubuntu, Kali, and Mint systems all on the same hard drive for security testing, development, and overall daily use. This involved partitioning the same drive multiple times, mounting ISO files onto a USB drive with Rufus, and BIOS configuration. This also involved managing the GUID Partition Table, or GPT architecture to ensure that each OS has a dedicated primary parition, while sharing a unified EFI System Partition, or ESP.

Technical Details

  • Media Creation: Downloaded the ISO file for each OS, them mounted it onto a USB with Rufus.
  • Firmware Optimization: Optmized the BIOS to ensure that the computer ran smoothly with multiple OS's.
  • Boot Control: Managed the GRUB and EFI boot managers for peak efficiency and reliability.

Challenges & Solutions

My first problem arose when I installed the second operating system, which replaced the GRUB loader of Kubuntu with Kali's, so I couldn't boot into Kubuntu. In order to fix it, I had to enable os-prober, which automatically detects other operating systems to ensure it doesn't overwrite anything related to other OS's. My second problem was after I downloaded all the Linux operating systems, which affected my clock in Windows to be off by several hours. I had to force Linux to use Local Time, which I did through timedatectl set-local-rtc 1 --adjust-system-clock. Finally, I had an issue with Kali and how it was missing Wi-Fi capabilities, which wasn't the case for Kubuntu and Mint, as Kali is a security tool. I had to do a manual firmware injection to ensure Kali has the proper firmware blobs it needed for my specific Wi-Fi card.

Arch Linux Installation

About This Project

This project involved the manual installation of Arch Linux, through the usage of the pacman package manager, downloading of custom greeters + window managers, and manual kernel configuration. Unlike other operating systems, Arch has you manually define each and every single component as you see fit, from the partition table, to the desktop compositor.

Technical Details

  • Manual Bootstrap + Pacstrap: This involved the two commands arch-chroot and pacstrap to install the kernel and to enter the new systenm environemnt.
  • Low-level System Configuration: This included the configuration of system files, that typically are automated in most other operating systems.
  • Window Management + Customization: Involves the choosing of the Xorg display server protocol, and download of the Hyprland window manager.

Challenges & Solutions

An issue I ran into was not having internet after restarting my computer once the installation was complete, caused by not having services enabled. In order to fix it, I had to download NetworkManager, and ensure it was enabled on startup in the chroot environment. Another issue I had was with booting into Hyprland, caused by not having all of the dependencies needed. I had to download the remaining dependencies, and ensure that hyprland detected the dependencies it needed. Finally, I had an isuse with constant screen tearing, caused by missing drivers. I had to manually identify the hardware, and install the correct drivers via pacman.

It also involved the step-by-step assembly of a root filesystem, management of USE flags that allow maximum customization, and the navigation of technical documentation to troubleshoot bootloader configuration.

Another issue I had was with with the GRUB bootloader, and how it wasn't giving me the option to boot into gentoo, and only showing me my UEFI settings. In order to fix it, I had to regenerate the kernel configuration file, and re-mount grub to the boot partition, as it was accidentally saved to my root folder. Finally, I had issues with installing the window manager, as when I ran the install command for Hyprland, it kept saying I was missing dependencies. To fix this, I had to manually install every single dependency, and deal with unmasking them aswell. The two dependencies that I had the most trouble with were aquamarine and LibHyprUtils.

SIEM and IDS/IPS Home Lab Deployment

About This Project

This project involved the architectural design of a segmented SOHO network, and the technical integration of a dedicated SIEM and IDS/IPS attack stack in order to simulate enterprise-level security monitoring. Through leveraging a Ubiquiti UniFi hardware suite alongside a Raspeberry Pi-based controller, the deployment isolated critical traffic while providing real-time visibility into potential network threats.

Technical Details

  • Network Hardware: Ubiquiti UniFi Security Gateway (USG) paired with a UniFi Switch 8 and Raspberry Pi 4 running as a dedicated local controller and SIEM node.
  • Security Protocol: Implementation of Suricata for a signature-based IDS/IPS monitoring and VLAN tagging to isolate IoT devices from the primary production environment.
  • Logging & Analysis: Automated log ingestion via a Syslog server, with data visualization and threat analysis managed through ELK Stack.

Challenges & Solutions

The first issue I came across during this project was after I enabled IDS/IPS, the console was flooded with hundreds of alerts for suspicious traffic. I had to preform signature tuning to analyze repeated alerts and manually disable signatures. Another issue I had was with the fact that heavy logging on a Raspberry Pi lead to high CPU usage and SD card failure. To fix it, I optimized the stack by using Logz.io, to offload the heavy database storage to an external SSD rather than an SD card. Finally, the last issue I had was caused by how HTTPS/TLS web traffic is encrypted, meaning my IDS/IPS couldn't see the actual data packets passing through the UniFI stack. I had to implement Heuristic and behavioral analysis.
